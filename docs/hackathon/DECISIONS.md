# ShopVoice — Decisions and spec deviations

Each entry: date, decision, why. Where the spec (`docs/hackathon/SPEC.md`) and code reality disagree, reality wins and the deviation is recorded here.

## 2026-09-25

**D1. Working branch is `claude/great-ritchie-094a7c`, not `feat/shopvoice-alexa-mcp`.**
The cloud session running this work may only push its assigned branch. The PR to `main` comes from that branch. The owner can rename it on GitHub if wanted; the history is unchanged.

**D2. The `pre-hackathon-baseline` tag exists locally but could not be pushed.**
It points at `a9f3cdb` (2026-03-31 12:03 +0700), the last commit before the Sep 1 submission window. The session's git proxy refuses tag pushes, so the owner must push the tag. See BLOCKERS.md B1.

**D3. The migration runner now accepts legacy migrations without `-- migrate:up/down` markers.**
Migrations 014–016 were committed without markers. `npm run db:v2:migrate` therefore failed on a fresh database at 014, which CI's "Apply V2 migrations" step would also hit. Editing 014–016 would change their checksums on databases that already applied them. Instead, `splitMigration` in both `scripts/v2/db_v2_lib.mjs` and `scripts/v2/remote_migrate.mjs` now treats `---- rollback` as the down separator, or the whole file as `up`.

**D4. `db/v2/seed/001_dev_seed.sql` is updated for the 012 renames.**
Migration 012 renamed `zalo_users` to `platform_users` and `zalo_user_id` to `user_id`. The dev seed still used the old names and failed, which blocked the spec's `npm run db:v2:seed -- --demo` quickstart. The fix is a minimal rename. The pre-existing `db:v2:test:rls` and `db:v2:test:bootstrap` scripts have the same staleness. They are out of scope and not changed; see BLOCKERS.md B3.

**D5. Migration 017 adds three tables beyond the spec's five.**
- `shop_profiles`: shop name, display currency, VND→display rate, timezone. This backs the `shop://profile` resource and the rule to give money in the shop's display currency.
- `suppliers`: no suppliers table existed. Invoices only carried a free-text `supplier_code`, and the spec needs "5 suppliers" plus spoken supplier names.
- `mcp_access_tokens`: per-tenant bearer tokens, stored only as SHA-256 hashes. The spec's "`MCP_TENANT_TOKENS` → hash lookup in DB" means the tokens have to live somewhere. A SECURITY DEFINER function `resolve_mcp_access_token(hash)`, owned by the BYPASSRLS `groceryclaw_bootstrap_owner` role, resolves a token before any tenant context exists. This is the same pattern as `resolve_membership_by_platform_user_id`.

**D6. Money columns: `sales_daily.revenue_display NUMERIC` instead of `revenue_display_currency`.**
`revenue_vnd BIGINT` is the source of truth. `revenue_display` is the amount in the shop's display currency, and the currency code lives once in `shop_profiles.display_currency`.

**D7. Confirmation tokens are stored hashed.**
`purchase_order_drafts.confirmation_token_hash` replaces the spec's plaintext `confirmation_token`. The token is returned once to the MCP client and expires after 5 minutes (`expires_at`). One `create_reorder_draft` call may create several drafts, one per supplier, all sharing one token.

**D8. Tenant FKs on the new tables use `ON DELETE CASCADE`.**
The existing RLS, bootstrap and real-DB fixtures run `DELETE FROM tenants`. Cascading keeps them working when demo data is present.

**D9. Demo data uses generic or fictional product and supplier names.**
Examples: "Cola 330ml Can" and "Sunrise Beverages". The demo-video rules forbid third-party trademarks on screen, so the spec's "Coca-Cola invoice" utterance becomes "Did the Sunrise Beverages invoice arrive?" or "…the drinks invoice…".

**D10. The demo shop's display currency is USD, at 25,000 VND = 1 USD.**
The judges and the video are English-speaking. VND is still stored, and a Vietnamese shop simply sets `display_currency = 'VND'`.

**D11. Demo seed dates are relative to an anchor date.**
The default anchor is today in Asia/Ho_Chi_Minh. Set `DEMO_ANCHOR_DATE=YYYY-MM-DD` to pin it for a reproducible video. Quantities come from a fixed PRNG (seed 20260901) × an ISO-weekday multiplier (Sat 1.45, Sun 1.35) × per-day noise of 80–120%. The seed SQL is generated by `scripts/v2/gen_demo_seed.mjs` and committed; a unit test fails if the two drift. Today's row is "so far", at 70% of a full day.

**D12. MCP SDK: `@modelcontextprotocol/sdk@1.30.1` (latest v1, 2026-09-23).**
The installed `dist/esm/types.js` has `LATEST_PROTOCOL_VERSION = '2025-11-25'`, so the spec's protocol version is the SDK default. The split v2 packages (`@modelcontextprotocol/server@2.1.0`) exist, but the spec names `@modelcontextprotocol/sdk` and v1 is the stable line.
